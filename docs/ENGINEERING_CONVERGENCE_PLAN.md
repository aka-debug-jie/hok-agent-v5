## 1. 项目目标与完成定义

最终目标是在固定自建测试场景中，让智能体根据真实 RGB 持续完成指定任务，并用实际
行动结果评价策略改进。当前先交付“目标导航”这一条窄链：固定布局、蓝方下路配置、
可解释的目标选择、连续移动与正确停止。英雄身份未绑定的录像只支持通用视觉研究，
不能自动当作后羿专用训练数据。身份/控制探针与规则导航按英雄无关处理；v0 的后羿/固定
分路绑定只适用于确有英雄身份数据的训练与执行配置，不反过来要求探针阶段先绑定英雄。

项目完成看行为：到达了哪里、何时停、为什么停、需要多少接管、下一次观察是否由本次动作产生。
测试数、分类准确率、产物数量和包大小只说明各自局部性质；不据此估算项目完成百分比。

后续分开记录四项能力，不再通过 R0/R1 名称的大小推导能力等级：

| 能力 | 当前证据 | 尚缺什么 |
|---|---|---|
| 运行工程 | 旧规则 runner 有 Store、终止先写和模拟中断恢复 | 最新多目标几何策略尚未接入同一 runner |
| 真实感知 | session 002 的旧定位 v2 仅部分时段可用；003/005 不支持连续定位 | 身份可靠且连续的玩家位置、与布局一致的目标 |
| 当前 Movement 学习 | 同生成器内曾通过；跨位置候选 dev accuracy 0.2083 | 有应用增量、可推广的策略；历史模型结果不能替代 |
| 实际应用 | 存在历史设备执行证据，本轮只做离线 | 当前方案在真实行动反馈下的表现 |

最新 10/10 是固定、两格 waypoint 的合成规则回放。352/352 使用精确合成标记。
这两者不证明任意路径规划、避障、实时吞吐或真实画面迁移。
历史其他路线的学习 checkpoint 继续保留，不与本轮 Movement 的拒绝结论混为一谈。

## 2. 为什么推进慢，以及对应的改法

| 已查明的问题 | 证据或限制 | 后续约束 |
|---|---|---|
| 用容易统计的指标代替目标行为 | 旧玩家候选接近全覆盖，实际混入右上角固定 UI | 同时展示失败画面和所有输入分母；覆盖不当身份准确率 |
| 把标签能生成当成任务可学习 | 摇杆状态可见，却不提供玩家下一步的战术目标；延续标签按定义可由前方向重现 | 先说明输入在决策时刻究竟含什么信息，再决定是否学习 |
| 拆分防住重复，却没防住任务捷径 | 最初 train/dev 都把 E/W 放在同一行；新路线暴露失败 | 按真实应用变化因素拆分：源对局、位置、布局、目标距离；hash 去重仅是基础 |
| 组件通过被表述成系统通过 | 新几何回放只写 JSON；恢复来自旧单目标规则 runner | 系统结论必须由同一次运行的观察、动作、Store 和恢复证据支持 |
| 一次失败后不断换版本继续研究 | 原型、合同、数据、对照、QA 和打包反复串联 | 预算和尝试次数挂在用户可感知的问题上，换 run ID 不重置预算 |
| 文档保存了多条互相冲突的“下一步” | 重订前 AGENTS 621 行、README 954 行、计划 869 行 | 当前入口只保留本计划、一个任务卡；历史按需读 |
| 预算有上限但累计实耗不完整 | 不能从过去的 80 小时规划推算剩余额度 | 旧总用时记 UNKNOWN；新批次记录实际时间，不补造历史数字 |

这些证据支持“数据/任务条件及泛化有问题”，不能单凭一次失败断言某算法永远无效，
也不能把增加参数视为必然解决办法。后续训练由可验证的应用问题驱动。

## 3. 最小运行结构与复用边界

```text
既有 RGB / PixelArena RGB
    → 玩家位置及可用状态 + 显式目标及来源
    → 确定性导航建议
    → Router 决定动作 / KEEP / STOP
    → 同一个 executor 接口
    → 下一观察 → UnifiedTransitionStore → 运行摘要与可视回放
```

- 近期规则导航负责根据可见位置和目标换向；Executor 维护方向，Router 管停止和重置。
  三个逻辑职责不要求三个神经模型。Combat/购买保留现有组件，暂不进入导航验收。
- 每个 100 ms 模拟 step 都重新观察有效性和到达条件。KEEP 不意味着可以忽略新画面：
  目标改变、到达、偏离或原有卡住条件、死亡/重置、来源过期都可能结束保持。
  不能把“换向一次 → 固定两步 → STOP”推广为任意路线算法。
- 已有配置选定的目标是任务条件，不冒充人类意图。模拟真值来源、真实 RGB 来源和
  预设布局坐标必须明确区分；规则可以使用声明的目标，RGB Actor 的输入边界不改变。
  从 RGB 无法定位时输出 unknown；未知停止单独计数，不算到达成功。
- 录像的后续画面由录制时的玩家动作决定，建议动作没有改变它。
  录像回放只能验证感知、建议及记录，不能生成伪造的执行 transition 或动作效果奖励。
- 复用 movement_real_rgb.py 的缓存读取/QA、movement_goal_canvas.py 的规则、
  movement_mvp.py 的运行与恢复、transition_store.py 的既有存储。
  只改当前触点；不先拆整个大文件，不加数据库、总线、调度服务或模型池。
- 旧 R0/D0 合同绑定代码，恢复时可能因修改源码而拒绝，这是可预期的。
  旧证据在冻结提交复核；新配置/运行 ID 绑定新代码，不能拿旧 partial run 测新恢复。
  模拟时间 100 ms 与墙钟耗时分开；模拟快跑不等于手机 10 Hz 实测。

## 4. 已完成批次：两个具体结果

N1/N2 顺序执行，同一时刻只有一个主任务。以下是新批次上限，不是旧预算的自动续期；
GPU 0，云/API 费用 0，新增派生产物合计不超过 512 MiB。不执行模型训练或重新扫描整批视频。
实际执行未训练模型、未连接设备，也未打开 test/holdout。

| 工作 | 工程上限 | 实际要交付 | 完成或结束条件 |
|---|---:|---|---|
| N1 真实输入可视演示 | 4 h | 一份既有 ROI 的可播放 QA 与一份 summary，显示玩家候选、目标、建议和 unknown | 可定位的时段与固定 UI/丢失时段都可见；完整计入覆盖、最长缺失、建议数。证据不足直接写 DATA_SOURCE_LIMITED |
| N2 同链集成 | 6 h | 多目标规则通过现有 runner 产生 Store、回放和恢复记录 | 新代码的连续/中断两次运行一致，目标切换和停止由每步状态决定，证据不再来自两个不相干的 runner |
| 回归与交接 | 2 h | 按风险检查、一个提交、账本一段结果 | 上述实际产物可复核；不新建交付包、报告签名链或第二次全量审查 |

### N1 的具体范围

1. 优先复用已绑定的 session 002/003/005 的派生帧与定位 v2/既有 QA；不重跑已失败提取器。
   002 取账本已确认的有效区间以及缺失区间；003/005 保留固定 UI/不支持片段作为负向例子。
   这些是目的明确的开发示例，不是随机测试集，不能由此报告总体精度。
2. 总展示不超过 120 秒、最多 3 个来源；缓存不足就展示实际可用长度并报告不足。
   不为凑时长重新解码原始视频、找新录像或要求用户录制/标注。
3. 复用 Pillow 输出低分辨率派生 ROI 动图/联系表时间序列；不建标注界面。
   每帧保留实际时间索引、候选来源、目标来源、建议和缺失原因；不填造玩家位置。
4. 至少展示同一画面两个不同目标的建议变化，以及定位无效时的 STOP；
   这验证目标条件和拒绝行为，不证明目标选得好或人类本来想这样走。
5. summary 明确 samples_total、定位可用数、最长 unknown、直接观测/离线补缺数、
   proposal_count、input_commands_sent=0。历史 QA/未来确认信息不得当实时可用定位。
6. 若没有任何新的身份/连续性证据，沿用“002 部分可用、003/005 不支持”的结论。
   本任务的增量是让问题可观看；不宣布定位算法已改善，不接着换光流或颜色规则。

### N2 的具体范围

1. 使用已有多 waypoint 路线作为回归配置，经现有 runner 的
   _packet → _transition → store.append 写入；复用现有状态/动作类型。
   配置启用多目标规则，旧配置仍运行原规则；不新增同义 CLI。
2. 源报告的两步脚本只用于旧回归对照。另设少量开发案例覆盖不同距离、目标中途切换、
   unknown 和停止后再出发；不打开旧 holdout，不把新增案例当未见测试。
3. 原场景的期望动作与已冻结规则一致；可变距离场景每步根据新观察到达后停。
   不把 120 设成所有新场景的硬性步数，也不重新训练去贴合这些案例。
4. 必须记录 episode/step、目标版本、观察引用、实际 applied_movement、STOP/KEEP、
   确定性模拟时间、终止类型；reward 为 0。
   恢复时从已提交行重建当前目标、previous_action 和连续 STOP 状态。
5. 连续运行与第 4 个已提交 transition 后的跨进程恢复比较内容摘要；
   终止行先写、无重复 step、引用完整。缺字段只扩现有版本，不另建 Store。
6. N1 不支持真实连续定位时，N2 仍可作为这一次有限的整机工程补齐；
   完成后固定记为 simulator-only。此后不得靠扩大模拟场景绕过真实数据瓶颈。

每项到时保存可复现结果及剩余工作；阻塞缺陷优先压缩范围。没有足够数据不必耗满额度。
若 N1 仍 DATA_SOURCE_LIMITED，N2 结束后本批次停止开发；下一决策必须改变数据来源或接受
局部应用范围，不能再从原视频、同一 detector 或同一模型自动开新分支。

## 5. 后续目标的条件顺序

下列为条件性规划，不在本次启动。每次只把一个满足前提的目标移入账本。

| 目标 | 启动前提 | 成果与预算建议 |
|---|---|---|
| P：真实目标导航可观察 | 已有新的独立玩家身份线索及真实布局目标绑定 | 先固定一套布局，2 个来源各 3 段 20 s 的开发回放；最多 8 h、GPU 0、1 GiB |
| L：一个有价值的学习组件 | P 成立，错误统计指出规则的具体不足，输入包含所需信息且有可用监督 | 1 个候选加最多 1 个针对同一原因的修正；16 h、4 GPU h、2 GiB；收益不成立就保留规则 |
| A：固定自建 App 行为 | 可观察链成立且存在对应设备任务授权/环境 | 复用已有接口完成 1→3→10 局；最多 16 h、GPU 0、1 GiB；单报接管和失败 |
| R：单策略后训练 | A 有稳定真实 transition，选定任务的反馈已独立检查 | 再单独给预算，冻结感知/反馈，只更新一个策略，与冻结初始策略同场景比较 |

P 成立且规则已满足任务时，可以直接进入 A；L 是有明确收益目标的可选工作，不是应用的强制前置。

P 的建议工程门在运行前固定：每来源有效定位 ≥80%、至少一段连续 10 s、QA 未发现固定 UI
冒认或明显身份切换；总分母含未知。缺独立参考时称“开发可用性”，不称定位准确率或置信度校准。
这些值是新任务的预算化目标，不能用来改写旧失败。最先比较当前真实数据是否足以承载 P，
证据不足时停止，不因方案写得完整就继续实现。

L 学什么取决于故障：可能是感知，也可能是目标选择；不强制神经网络重学精确几何方向。
三策略分工和后续 RL 方向保留，但不预建三个模型。规则已足够时没有强制训练里程碑。
A 的任务成功是具体到达并停止，不能用胜率代替导航验收。
R 不需要先补齐 HP/塔伤/经济/胜负全部 CV，只需要当前任务足够可靠的反馈；
同一个未经验证的 detector 不能同时制造 reward 并充当准确性证明。

数据路径只有两个诚实的选择：
- 继续用已有数据：接受只在证据支持的可见时段工作，不能承诺完整实战导航。
- 获得新的自动参考：若确有可修改的自建 App 源码，可另议测试专用的身份/位置参考用于
  评估或自动监督，部署 Actor 仍读 RGB；目前未核实源码存在，不默认实现或连接。
无需要求用户做人工标签。没有新参考、也不接受局部范围时，真实自主应用应明确记为受数据限制。

用户选择的 session002 局部范围已通过 P0 Shadow 完整量化：208/1,485帧可直接定位，
27个有效片段，最长仅6.6秒。它未达到本节的80%覆盖和连续10秒门，因此局部路线到此结束；
后续导航只接受新的独立玩家位置参考，不再重跑相同录像或定位规则。

用户随后确认项目目标是无源码视觉控制。已有动作记录的独立审计表明，session002内区候选
在17个唯一动作对中有14个沿发送方向移动至少1像素，而三局45个固定UI动作对为0；动作不参与
候选生成。该结果支持下一步设计受控的多方向主动探针，但只在session002成立，不能代替跨局
身份验证。未来探针仍须复用现有设备门禁，并用新的动作序列验证，不能用本审计数据重复宣称通过。

### 探针失败分支与全局停止条件（2026-09-14 预声明，运行前生效）

- 两个新会话都未通过 A 门时：停止该探针路线，不得降低门槛、缩短观察窗、更换会话或复用
  本批数据重复宣称通过。随后只允许三选一：(a) 自建 App 源码可改时，改为提供测试专用的
  位置/身份参考（部署 Actor 仍只读 RGB）；(b) 采集新的录像/会话重建身份线索；(c) 接受
  “数据源受限的局部范围”，停止真域学习投入。
- 全局停止条件：无源身份/控制可观察性在两次预算化探针批次内仍未建立，即判定该方向受
  数据源限制，转入只读或局部范围；不得靠新 run ID、新阈值或扩大模型延续同一问题。
- 以上分支同时写入主动探针契约的 `failure_policy`，会话运行前冻结，运行后不得解释性放宽。

## 6. 数据和训练纪律

- 50 GB 是字节规模，不是有效监督规模。报告独立对局、独立时间窗口、有效标签和
  各方向/事件在各来源的支持数；目标环增广不增加独立源窗口数。
- 学习标签必须写明是“实际派发动作”“屏幕摇杆弱状态”还是“合成目标方向”；
  执行器确认也不等于角色一定完成位移。标签缺失、unknown 和 STOP 分开。
- 观察窗口不跨局，结束于决策可用时刻；重叠或同源增广不跨 split。
  在时间/几何存在偏差时先定义可部署信息，再选时序长度；不默认 16 帧一定优于单帧。
- 新学习问题先与最便宜的合理规则比较。存在已解释该目标的精确规则时，不先排神经训练。
  每个模型只做直接检验当前假设的对照；不固定要求所有模型、消融和重复 seed 全跑。
- 32 样本用于数据/梯度/模式 sanity check，复用正式 train_step；
  它不证明泛化，也不是所有后续任务必须再过一遍的独立阶段。
  历史诊断次数已消耗，不重开；新任务只在输入/标签/实现确实变化后才需要新的小检查。
- 固定开发场景可以排查和调试，但必须报告已使用；正式 test 不参与选择。
  已消费的 test 不重开。源哈希无交叉不代表几何或语义独立。
- 候选需在同一场景与当前应用基线比较：主指标预先确定一个，如到达率或最长失联时间；
  同时报碰撞、过早停止、接管和延迟等相关退化，失败和 unknown 计入分母。
  规则接管后的到达不能计成纯学习成功。无独立参照时不声称泛化已证实。
- 不同时改感知、标签、采样、模型和 reward。实现 bug 的修复计工程时间，
  不机械消耗科学假设次数；改变模型/任务/训练数据选择则计候选，最多两次同问题尝试。
  新 run ID 或配置版本不重置该问题的时间与尝试预算。

## 7. 工作量、代码体量与交付

- WIP=1 个主功能 + 1 个直接阻塞项。已授权、预算内的可逆离线步骤由开发者连续完成。
  只有目标、数据来源、外部动作或预算发生实质变化，才带具体证据提出需要用户决定的选项。
- 单个任务必须有 2–6 小时内可运行的最小结果；最晚 4 个有效工程小时交付一次
  行为证据或一个已排除的阻塞原因。承诺的是反馈周期，不承诺算法一定成功。
- 同一假设连续两次没有主指标改善就结束；一次失败被证据直接否定时可提前结束。
  技术难点、数据不足、实现 bug 分开说明，不用“新合同”规避退出。
- 目标代码净增默认 ≤300 行/任务、最多触及 3 个生产模块；这是设计复盘线而非运行门禁。

## 9. 按风险验证与日常入口

| 变更 | 足够的检查 |
|---|---|
| 文档/计划 | diff、链接、状态/预算一致性；无需训练、pytest 或第二代理验收 |
| 局部逻辑 | 能覆盖实际失败的聚焦回归 + Ruff；类型/API 变化加 mypy |
| 观察/动作/Store/恢复 | 同链集成、终止/重复/恢复回归 + strict mypy；边界变化加项目检查 |
| 可运行版本交付 | 一次完整 make check + 真实运行证据 + git diff --check |

检查绑定源码版本。后续仅改文档不使已通过代码检查失效；交付后若修代码，补受影响回归并
如实区分验证时点，不能把旧全量结果冒充为新代码的全量结果。避免测试只照抄实现常量。

当前工作树共享相邻项目的既有环境，读取时实测 Python 3.11.15，pyproject 要求 ≥3.11。
运行命令显式绑定解释器和本工作树 src，不修改全局环境：

```bash
env -u LD_LIBRARY_PATH PYTHONPATH="$PWD/src" ../hok-agent-v5/.venv/bin/python -m hok_agent movement-mvp --help
make PYTHON=../hok-agent-v5/.venv/bin/python check
```

第一条只查看现有 CLI；N1 尚无新命令，实施时接入已有入口再给出真实命令，不在计划里伪造。
第二条仅用于相应风险层级的可运行交付，不在每次文档提交执行。
冻结包继续用现有 verify-only 复核，不能用它代替新的端到端行为验证。
